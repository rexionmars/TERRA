# Changelog

Every release, and what changed in it for someone using the application.

FEATURES, FIXES AND PERFORMANCE ARE LISTED; the rest is counted. A refactor
that moves ten thousand lines and changes no behaviour is not news to a reader
deciding whether to update, and a list that mixes the two teaches the reader to
skip both. The counted work is in the git history, which is where it is useful.

Kept by [release-please](https://github.com/googleapis/release-please) from
[Conventional Commits](https://www.conventionalcommits.org/) from v0.5.0 on.
The entries below it were written from the same history after the fact, which
is why they are terser than the ones that follow.
